## Clarifications

### Session 2026-11-18

- Q: 侧栏面板与“插件”页配置页共用同一形式后，配置页具体承担什么？ → A: 效果与侧栏面板相同：新增、删除、配置 MCP 服务器，并发起授权。
- Q: 面板与配置页新增或修改的服务器定义保存到哪里？ → A: 通过宿主的配置表单写回 profile 的插件行配置（用户层），profile 是定义的事实源。
- Q: OAuth 预置 clientSecret 放在哪里？ → A: 与访问令牌、刷新令牌一起存入 DSH 凭据库；配置文件不出现任何密钥。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按服务器懒加载 (Priority: P1)

用户在一个 profile 里配置多台 MCP 服务器。设为懒加载的服务器在启动时只登记、不连接；模型第一次调用它时，插件自动挂载、等待连接并执行，挂载后保持常驻。用户也可以在面板里随时切换懒加载与常驻。

**Why this priority**: 多台 MCP 服务器会拖慢启动并挤占工具表；懒加载让只登记不连接成为可能。

**Independent Test**: 配置两台懒加载服务器并启动插件，确认都没有连接；用 `mcp_call` 调用其中一台的工具，确认它完成挂载并返回工具结果；`mcp_servers` 列出两台的状态、工具数与懒加载标记。

**Acceptance Scenarios**:

1. **Given** 某服务器定义为懒加载，**When** 插件启用，**Then** 该服务器不建立连接，工具表里没有它的原生工具。
2. **Given** 懒加载服务器尚未挂载，**When** 模型调用 `mcp_call` 指定该服务器与工具，**Then** 插件先挂载并等待连接，再执行工具并返回内容与错误标记。
3. **Given** 面板显示懒加载服务器，**When** 用户关闭懒加载开关，**Then** 服务器立即挂载并常驻；再次打开开关，服务器卸载。
4. **Given** 服务器已连接，**When** 用户点重连，**Then** 插件卸载并重新挂载该服务器，面板状态随后更新。
5. **Given** 服务器在启动时非常驻且连接失败，**Then** 面板显示失败原因，其它服务器不受影响。

### User Story 2 - 可视化 OAuth 登录 (Priority: P1)

某台 MCP 服务器对未授权请求返回 `401`。用户在面板点“授权”，插件按 MCP 授权规范完成发现、动态注册与 PKCE，把浏览器带到登录页；回调后令牌写入 DSH 凭据库并自动挂载。令牌过期前插件自动刷新；用户可重新授权或退出登录。

**Why this priority**: 现在用户必须手写 token 到 MCP 配置里，既难用又会把凭据留在明文配置中；OAuth 让登录变成一次点击。

**Independent Test**: 对返回标准 `401` 与授权元数据的服务器启动授权，在浏览器完成登录后确认服务器自动连接、工具可用，且配置文件中没有令牌；退出登录后服务器卸载。

**Acceptance Scenarios**:

1. **Given** 服务器返回 `401` 并给出受保护资源元数据，**When** 用户启动授权，**Then** 插件发现授权服务器与令牌端点，并打开带 PKCE 挑战的授权页。
2. **Given** 授权服务器支持动态注册，**When** 插件没有预置客户端凭据，**Then** 插件先注册客户端再发起授权。
3. **Given** 服务器钉死回调地址与客户端，**When** 用户启动授权，**Then** 插件在同一台机器的固定回环端口监听回调，登录完成后关闭监听。
4. **Given** 回调带回授权码，**When** 插件换取令牌，**Then** 授权记录写入凭据库，服务器按当前懒加载设置重新挂载。
5. **Given** 已存授权接近过期，**When** 需要访问该服务器，**Then** 插件先用刷新令牌换新令牌；刷新失败时沿用旧令牌并记录告警。
6. **Given** 用户点退出登录，**Then** 授权记录删除，服务器卸载。
7. **Given** 服务器的 `401` 不提供标准授权元数据，**Then** 插件返回可读错误，提示改用固定客户端配置。

### User Story 3 - 把插件工具聚合成一个 MCP 端点 (Priority: P1)

用户在本机暴露一个按组划分的 MCP 端点，每个组用工具名通配符选出一批宿主工具，用 Bearer 令牌保护。外部 MCP 客户端（Claude Desktop、另一台 DSH、脚本）可以列出并调用这些工具。

**Why this priority**: 让本机的工具能力可以被外部 MCP 客户端复用，不需要为每个工具单独适配。

**Independent Test**: 用令牌对某组发送 `initialize`、`tools/list` 与 `tools/call`，确认返回的协议信息、工具清单与真实执行结果一致；用错误令牌确认被拒绝。

**Acceptance Scenarios**:

1. **Given** 组 `harness` 包含 `workspace_*` 与 `session_*`，**When** 外部客户端列出工具，**Then** 只返回同时匹配该组包含与排除规则的工具。
2. **Given** 请求不带令牌或令牌错误，**Then** 端点返回 `401` 并要求 Bearer 认证。
3. **Given** 请求调用组外工具或不存在的工具，**Then** 返回明确的参数错误，不执行任何工具。
4. **Given** 工具执行成功，**When** 端点回包，**Then** 文本内容映射为 MCP 内容块；工具报错时回包标记为错误。
5. **Given** 用户轮换访问令牌，**Then** 新令牌生效、旧令牌立即失效。
6. **Given** 用户关闭聚合端点，**Then** 该端点返回未找到。
7. **Given** 一次 JSON-RPC 批量请求，**Then** 通知类消息不回包，无效消息返回标准错误码，批大小有上限。

### User Story 4 - 侧栏面板与插件页入口 (Priority: P2)

用户在侧栏底部“重启 DSH”右侧看到 MCP 图标，点开面板查看每台服务器的状态、工具数、懒加载开关与授权按钮，以及聚合端点地址与令牌。面板还能新增、编辑、删除本插件管理的服务器并发起授权。同一个面板内容也出现在“插件”页本行的配置页里，两处能力和结果一致。

**Why this priority**: 面板是懒加载、OAuth 与服务器定义的主要操作面；插件页入口让用户从配置入口也能到达同一组操作。

**Independent Test**: 在侧栏点图标打开面板，新增一台服务器并完成授权，确认它出现在列表并连接；在“插件”页打开本行详情，确认出现同一组服务器事实与操作，并能编辑与删除同一台服务器。

**Acceptance Scenarios**:

1. **Given** Web GUI 已加载，**When** 用户看侧栏底部，**Then** MCP 图标位于重启按钮右侧，折叠与展开两种宽度都可点击。
2. **Given** 面板已打开，**Then** 它列出本插件配置的服务器与宿主管理器里的其它服务器，并用标记区分两者。
3. **Given** 本插件的服务器，**When** 用户操作开关、重连、授权、退出，**Then** 面板在操作完成后显示最新状态。
4. **Given** 聚合端点已启用，**Then** 面板显示每个组的地址与标题、复制按钮，以及可显示、复制、轮换的访问令牌。
5. **Given** 界面语言为中文或英文，**Then** 面板文案跟随语言。
6. **Given** 读取状态失败，**Then** 面板显示错误与重试按钮。
7. **Given** 用户新增服务器并保存，**Then** 定义写回插件行配置，服务器出现在列表并按其懒加载设置挂载。
8. **Given** 用户编辑服务器定义并保存，**Then** 插件卸载旧定义、按新定义重新挂载，列表显示最新状态。
9. **Given** 用户删除本插件管理的服务器，**Then** 定义从配置移除、服务器卸载、其授权记录清除。
10. **Given** 用户在“插件”页打开本行，**Then** 出现与侧栏面板相同的服务器列表、增删改与授权操作。

### User Story 5 - 模板转化交付 (Priority: P2)

维护者把模板仓库改造成真实插件：仓库标识、文档与发布门禁按本插件重写，旧模板 spec 与 changelog 清空，首版可安装、可构建、可发布。

**Why this priority**: 没有这一步，交付物仍是“模板 + 示例实现”，用户无法把它当作插件安装。

**Independent Test**: 从干净 clone 执行安装、构建与检查，按 README 把插件行加入 profile 后能在宿主加载。

**Acceptance Scenarios**:

1. **Given** 干净 clone，**When** 运行仓库检查命令，**Then** 类型检查、lint、测试与构建全部通过。
2. **Given** 插件行插入 profile，**When** 宿主启动，**Then** 插件加载并注册工具、路由与面板入口。
3. **Given** 仓库根目录，**Then** 包名、README、AGENTS、宪章与本地 skill 均指向本插件，不残留模板示例。
4. **Given** 交付的配置示例，**Then** 只出现服务器结构与 OAuth 非密钥参数，不出现任何令牌或客户端密钥。
5. **Given** 版本标签推送，**Then** CI 发布 job 可用，并在 README 提示绑定 npm Trusted Publisher。

### Edge Cases

- 授权服务器的动态注册端点拒绝注册，或服务器钉死客户端与回调端口时，用户需要显式填写客户端与回调。
- 固定回环端口被占用时，授权启动失败并清理待处理状态，面板显示原因。
- 懒加载状态文件缺失或损坏时，按空状态处理，回退到配置里的默认懒加载值。
- 配置里没有任何服务器时，面板只显示宿主管理器里的其它服务器，聚合端点仍可用。
- `mcp_call` 指定的服务器未配置、工具名不存在，或服务器连接超时、失败、等待凭据、返回 `401` 时，分别给出可读错误。
- 两台服务器同名注册时，宿主管理器拒绝冲突，插件把冲突原因报告给调用者。
- 新增的服务器名与既有服务器或管理器里的服务器重名时，保存被拒绝并提示重名。
- 新增定义缺少传输方式、stdio 命令或 HTTP 地址时，保存被拒绝并提示缺失字段。
- 编辑正在连接的服务器时，插件先卸载旧定义，再按新定义挂载。
- 删除服务器时仍有进行中的授权，插件取消待处理授权并关闭回环监听。
- 配置写入被更高层覆盖或部署只读时，面板显示未接受，保留用户输入供修改。
- 聚合端点调用的工具需要 Agent 上下文（例如工作目录写模式）时，执行失败并以错误内容回包。
- 浏览器拦截授权弹窗时，面板把授权地址显示出来供用户手动打开。
- 访问令牌或刷新令牌不得出现在配置文件、状态文件与日志中。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 插件 MUST 在启用时读取配置中的服务器定义与聚合端点设置，解析失败时让插件加载失败。
- **FR-002**: 插件 MUST 把每台服务器的懒加载值解析为“运行时状态优先，配置默认兜底”。
- **FR-003**: 插件 MUST 持久化用户在面板切换的懒加载值，重启后保持不变。
- **FR-004**: 插件 MUST 在启动时只挂载非常驻服务器，懒加载服务器保持登记状态。
- **FR-005**: 插件 MUST 提供 `mcp_servers` 工具，返回服务器状态、工具数、懒加载与授权标记、聚合端点组地址。
- **FR-006**: 插件 MUST 提供 `mcp_call` 工具，按需挂载目标服务器、等待连接、调用其工具并返回内容与错误标记。
- **FR-007**: 插件 MUST 支持在面板把服务器在懒加载与常驻之间切换，并立即挂载或卸载。
- **FR-008**: 插件 MUST 支持重连一台本插件挂载的服务器。
- **FR-009**: 插件 MUST 通过宿主管理器挂载服务器，由管理器负责连接、重连、工具发现与卸载。
- **FR-010**: 插件 MUST 按 MCP 授权规范完成受保护资源发现、授权服务器发现、可选动态客户端注册与 PKCE 授权。
- **FR-011**: 插件 MUST 支持为用户预置的客户端凭据与固定回调地址，并在固定回环地址上临时监听回调。
- **FR-012**: 插件 MUST 把授权记录存入 DSH 凭据库，并在挂载请求中自动带上 Bearer 令牌。
- **FR-013**: 插件 MUST 在令牌临近过期时用刷新令牌换新；刷新失败时继续使用旧令牌并记录告警。
- **FR-014**: 插件 MUST 提供退出登录，删除授权记录并卸载服务器。
- **FR-015**: 插件 MUST 提供聚合端点，把组内工具通过 MCP 协议暴露给外部客户端，支持初始化、工具列表与工具调用。
- **FR-016**: 插件 MUST 用通配符包含与排除规则选择组内工具；包含为空时排除所有 MCP 原生工具。
- **FR-017**: 插件 MUST 用 Bearer 令牌保护聚合端点，令牌存入凭据库，支持显示、复制与轮换。
- **FR-018**: 插件 MUST 拒绝未知组、关闭状态下访问端点、错误令牌、无效 JSON-RPC 消息与超量批量。
- **FR-019**: 插件 MUST 在 Web GUI 侧栏底部提供 MCP 入口并打开面板。
- **FR-020**: 插件 MUST 在“插件”页本行提供入口，以与侧栏面板相同的形式呈现同一组服务器事实与操作。
- **FR-021**: 面板 MUST 中英文随界面语言切换。
- **FR-022**: 面板失败时 MUST 显示错误与重试。
- **FR-023**: 插件 MUST 在“插件”页与 README 中清楚说明配置结构，示例不得包含访问令牌或客户端密钥。
- **FR-024**: 仓库 MUST 完成模板转化：包名与仓库标识改为本插件，README、AGENTS、宪章与本地 skill 同步改写。
- **FR-025**: 仓库 MUST 清空模板时期的 spec 与 changelog，仅保留本次需求的 spec。
- **FR-026**: 仓库 MUST 以 0.1.0 作为首版，恢复 CI 的发布 job，并提示绑定 npm Trusted Publisher。
- **FR-027**: 仓库 MUST 保持公开引用规则：跟踪文件不出现本机绝对路径、凭据与仓库外相对路径。
- **FR-028**: 面板与配置页 MUST 支持新增本插件的 MCP 服务器定义，包含名称、传输方式、命令或地址、认证方式与懒加载默认值。
- **FR-029**: 面板与配置页 MUST 支持编辑与删除本插件管理的服务器定义；删除 MUST 同时卸载服务器并清除其授权记录。
- **FR-030**: 服务器定义的增删改 MUST 通过宿主配置表单写回插件行配置的用户层，插件数据区 MUST 只保存懒加载状态与凭据引用。
- **FR-031**: OAuth 客户端密钥 MUST 存入 DSH 凭据库；配置中 MUST 只保留客户端标识、回调地址与授权服务器地址等非密钥字段。
- **FR-032**: 服务器定义保存后 MUST 在当前运行中生效：新定义挂载、移除定义卸载、变更定义先卸载再挂载，不需要重启 DSH。
- **FR-033**: 新增或编辑提交前 MUST 校验名称格式与传输方式所需字段；校验失败时 MUST 拒绝写入并提示原因。
- **FR-034**: 其它插件注册的服务器 MUST 只读呈现，不可编辑或删除。

### Key Entities

- **MCP 服务器定义**: 传输方式、端点或启动命令、请求头、环境、懒加载、认证方式与授权参数。
- **懒加载状态**: 服务器名到布尔值的映射，持久化在 DSH 家目录的插件数据区。
- **授权记录**: 访问令牌、刷新令牌、过期时间、客户端标识与密钥、令牌端点、资源标识、授权服务器元数据。
- **客户端凭据记录**: 用户为固定客户端填写的 clientSecret，与授权记录同存凭据库。
- **聚合访问令牌**: 一个单值凭据，用于外部客户端访问聚合端点。
- **工具组**: 组名、标题、包含通配符、排除通配符。
- **面板快照**: 服务器行（状态、工具数、懒加载、授权、是否本插件管理）与聚合端点信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 服务器正常时，首次 `mcp_call` 在 25 秒内完成挂载并返回结果。
- **SC-002**: 面板操作后 2 秒内显示最新服务器状态。
- **SC-003**: 配置文件、状态文件与日志中检索不到访问令牌、刷新令牌或聚合令牌。
- **SC-004**: 外部客户端列出的工具数与组内匹配规则的注册工具数一致，误差为 0。
- **SC-005**: 授权流程在标准 MCP 授权服务器上无需手写令牌即可完成，成功率达到一次点击完成。
- **SC-006**: 侧栏面板与插件页配置页对同一服务器的状态与操作一致，无信息差异。
- **SC-007**: 干净 clone 上的完整检查命令一次通过。
- **SC-008**: 仓库跟踪文件中不再出现模板示例与旧 spec，模板标识残留为 0。
- **SC-009**: 新增服务器保存后 5 秒内在当前运行中出现并按其懒加载设置挂载，无需重启 DSH。

## Assumptions

- 运行宿主为 DSH 0.2.2-rc.3；新增的宿主包依赖与该版本一致。
- 目标 MCP 服务器遵循标准 MCP 授权发现；不遵循的服务器由用户填写客户端与令牌端点配置。
- 聚合端点只监听本机 Web GUI 的端口，外部客户端在可达该端口的环境中工作。
- 面板只在同源 Web GUI（含配对的手机页面）中使用，不依赖 Remote 命名空间。
- 服务器定义只来自 profile 的插件行配置；插件不写 profile 的补丁文件，运行期增删改经宿主配置表单写入用户层。
- 侧栏入口与插件页入口共用同一个面板组件与同一组接口。
- 新增与编辑只作用于本插件管理的服务器；其它插件注册的服务器只读。
- 模板转化采用首个发布版本 0.1.0，并恢复默认禁用的发布 job。
- 安装补丁默认不预置任何服务器；README 提供 figma 与 chrome 的配置示例，其中不含令牌。
