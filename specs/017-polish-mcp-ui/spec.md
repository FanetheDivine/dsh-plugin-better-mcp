# Feature Specification: MCP 管理界面视觉优化

**Feature Branch**: `fix/017-polish-mcp-ui`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "自行解决ui问题。现在的ui太丑了 且不符合dsh的风格。 /real-device-test 在实机上截图并优化；注意亮/暗两种模式都要正常显示。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 清晰管理 MCP 服务器 (Priority: P1)

用户在 MCP 面板查看服务器、识别连接状态并执行常用操作。界面与 DSH 管理页面保持一致，信息层级清楚，操作易于查找。

**Why this priority**: 服务器列表是用户管理 MCP 的主要入口，状态与操作的可读性直接影响核心任务。

**Independent Test**: 在真实 DSH 中分别使用亮色和暗色模式打开包含多种状态服务器的面板，检查列表、状态、地址与操作按钮，并完成一次刷新和懒加载切换。

**Acceptance Scenarios**:

1. **Given** 面板中存在多个服务器，**When** 用户查看列表，**Then** 每个服务器的名称、状态、连接信息和可用操作具有明确层级，内容无重叠或截断。
2. **Given** DSH 使用亮色或暗色模式，**When** 用户打开或切换面板，**Then** 文本、状态、边框、输入控件和按钮在当前模式下均清晰可辨。
3. **Given** 面板处于加载、空列表或错误状态，**When** 用户查看反馈，**Then** 当前状态与下一步操作明确，布局保持稳定。

---

### User Story 2 - 顺畅新增与编辑服务器 (Priority: P2)

用户从侧栏弹窗或插件配置页新增、编辑服务器。表单与面板风格统一，字段分组明确，校验和操作反馈清晰。

**Why this priority**: 新增与编辑是配置 MCP 的关键流程，两种入口需要一致且可读的交互体验。

**Independent Test**: 在真实 DSH 的两种入口中分别打开新增或编辑表单，切换传输与认证选项，触发一次校验错误，并检查亮色和暗色模式截图。

**Acceptance Scenarios**:

1. **Given** 用户打开新增或编辑表单，**When** 查看并填写字段，**Then** 标签、输入区、可选配置与提交操作层级明确，当前模式下的内容完整可读。
2. **Given** 表单存在输入错误或服务端错误，**When** 用户提交，**Then** 错误信息清晰可见，已有输入保留，取消与保存操作可辨。
3. **Given** 可用空间有限，**When** 用户查看长地址或展开完整表单，**Then** 内容可滚动或换行，主要操作保持可达。

### Edge Cases

- 空列表、加载失败与操作失败应提供明确反馈。
- 长服务器名、长地址、长错误信息与多个状态标记不应挤压主要操作。
- 连接中、未授权、已连接与失败状态应在两种主题下可区分。
- 弹窗与内联配置页应保持一致的信息层级和控件样式。
- 主题切换后无需刷新即可保持可读性。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 面板 MUST 采用与 DSH 管理页面一致的布局、间距、字体层级和控件外观。
- **FR-002**: 所有界面颜色 MUST 随宿主当前主题适配，亮色与暗色模式均须保持文字和控件可辨。
- **FR-003**: 每个服务器条目 MUST 清楚区分名称、状态、描述、连接信息和操作区域。
- **FR-004**: 常用操作 MUST 具有一致的视觉优先级，危险操作 MUST 与常规操作明确区分。
- **FR-005**: 懒加载开关 MUST 具有明确标签和可识别的开关状态，并保留禁用与忙态反馈。
- **FR-006**: 新增与编辑表单 MUST 在弹窗和内联配置页使用一致的字段、输入控件、错误提示与操作样式。
- **FR-007**: 加载、空列表、加载失败、操作失败与授权链接 MUST 使用清晰且统一的反馈样式。
- **FR-008**: 长文本与有限宽度下 MUST 保持内容可读和操作可达。
- **FR-009**: 现有服务器管理、授权、表单校验和配置保存行为 MUST 保持不变。
- **FR-010**: 优化结果 MUST 在真实 DSH 中通过亮色与暗色模式的截图和核心交互验证。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 服务器列表、新增表单和编辑表单在亮色与暗色模式下的实机检查全部通过，文字、边框、状态和操作控件均可辨。
- **SC-002**: 两个入口的核心管理流程验证通过率达到 100%，包括打开面板、新增或编辑、刷新、懒加载切换与错误反馈。
- **SC-003**: 常见桌面宽度及有限宽度下，验证页面均无非预期横向溢出、控件重叠或主要操作不可达。
- **SC-004**: 实机复测中无界面脚本错误，现有服务器管理与配置保存回归用例全部通过。

## Assumptions

- 优化范围为 MCP 侧栏弹窗与插件配置页的服务器列表、状态反馈和新增/编辑表单。
- 现有功能流程、数据结构与配置格式保持不变。
- 以当前 DSH 插件管理页面作为视觉一致性参照。
- 实机验证覆盖宿主支持的亮色与暗色模式，以及常见桌面窗口宽度。
