# Research: MCP 管理界面视觉优化

## 实机证据

- DSH `0.2.2-rc.3` 的隔离 profile 已通过装载、工具表、客户端模块、配置写入与删除用例。
- 亮色系统主题中，面板卡片背景为 `rgb(27, 28, 31)`，正文为 `rgb(15, 17, 21)`，文字可读性不足。
- 服务器错误与状态处于同一文本行，长诊断挤压名称和操作。
- 完整表单超过弹层可视区时，标题与字段会离开可视区域。
- 浏览器基线未报告脚本错误。

## 决策

### 主题

- **Decision**: 所有表面、文字、边框、状态与遮罩使用宿主 `--dsw-alias-*` token。
- **Rationale**: 宿主系统主题切换会同步更新 token，界面可即时适配亮色与暗色。
- **Alternatives considered**: 固定色无法适配双主题；插件自定义媒体查询会形成独立主题体系。

### 列表

- **Decision**: 使用插件管理页的分隔行结构，将名称与简介、状态与开关、地址与诊断、操作分区。
- **Rationale**: 管理页的行结构能稳定容纳长文本，并保持扫描顺序一致。
- **Alternatives considered**: 独立卡片增加边框与视觉噪声；单行拼接难以容纳长错误。

### 控件

- **Decision**: 按宿主源码几何与交互实现插件自有 Button、Switch 和 Modal，样式使用插件前缀类名。
- **Rationale**: 宿主要求插件自行实现控件，复制已验证的样式与语义可保持一致。
- **Alternatives considered**: 运行时导入宿主 Client 组件违反宿主边界；原生复选框缺少宿主开关语义。

### 表单与确认

- **Decision**: 新增、编辑与删除确认使用统一弹层；表单正文独立滚动，底部操作固定；错误关联到具体字段。
- **Rationale**: 列表保持稳定，长表单与校验错误具有明确的浏览和焦点顺序。
- **Alternatives considered**: 内联展开会推动列表位置；仅显示全局错误难以定位字段。

### 验证

- **Decision**: 单元测试覆盖结构与语义，真实宿主覆盖亮暗主题、两种入口、长文本、校验与核心操作，并保留截图。
- **Rationale**: 静态测试可回归契约，真实渲染可验证主题 token、布局与宿主集成。
- **Alternatives considered**: 模拟页面无法证明宿主中的实际表现。
