# 流程契约：访谈与审查门禁

| 阶段 | 进入条件 | 完成条件 | 未完成时的返回阶段 |
| --- | --- | --- | --- |
| specify | 用户提出变更 | 规格草稿、质量清单与待确认决策已写入 | 当前阶段 |
| clarify | specify 已完成 | 需求探索与分批访谈完成，当前完整规格为 `Approved` 或 `Waived` | 当前阶段 |
| plan | 规格门禁通过 | 技术探索与实现细节访谈完成，当前完整计划为 `Approved` 或 `Waived` | 规格门禁失败返回 clarify |
| tasks | 规格与计划门禁通过 | 任务按用户故事与依赖顺序生成 | 规格失败返回 clarify，计划失败返回 plan |
| implement | 规格、计划与任务门禁通过 | 各阶段任务完成并提交，质量检查通过 | 新需求问题返回 clarify，新实现选择返回 plan |

## 访谈批次

1. 每段访谈先完成对应仓库与技术探索。
2. 每批提出依赖已满足的全部独立问题，并附推荐答案与理由。
3. 依赖未满足的问题进入后续批次。
4. 回答写回对应文档后重新计算后续批次。
5. 用户明确豁免时记录未确认事项与风险。

## 审查

- 批准只针对当前完整文档。
- 部分认可需要继续处理反馈并重新审查完整版本。
- 实质修改使既有批准或豁免失效。
- 豁免记录列出全部未确认事项与风险。

## 实现中的新未决项

实现中出现新需求问题或实现选择时，暂停受影响工作并返回对应探索、访谈与审查。门禁恢复后继续任务。
