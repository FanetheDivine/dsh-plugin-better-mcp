## Clarifications

### Session 2026-11-19

- [D-001] Q: 桌面端点击授权后，授权页在哪里打开？ -> A: 保持 a 标签，由宿主决定具体行为；使用 a 标签的目的正在于此。
- [D-002] Q: 授权链接是否必须提供可复制、可访问的完整地址？ -> A: 必须提供。
- [D-003] Q: 桌面端与 web 是否共用同一授权入口、同一文案与同一交互？ -> A: 共用。
- [D-004] Q: 授权地址尚未就绪时，入口如何表现？ -> A: 用户跳过提问；鉴权行在完整地址可用后才渲染，因此不单独显示准备状态。
- [D-005] Q: 验收是否必须包含打包后的桌面应用实机验证？ -> A: 测试通过即可。
- [D-006] Q: 默认浏览器无法打开授权页时，面板是否显示失败提示？ -> A: 由 D-001 推导：面板只渲染链接，打开失败归宿主处理，面板不新增提示。
- [D-007] Q: 已授权的服务器是否继续提供重新授权入口？ -> A: 不提供；需要重新登录时先退出登录。
- [D-008] Q: 授权行如何组合文字与链接？ -> A: 「点击鉴权」文字加完整地址链接，地址本身就是链接文本。
- [D-009] Q: 授权行里的完整地址指向哪里？ -> A: 插件鉴权启动地址，点击后由服务端跳转到鉴权页。
- [D-010] Q: 界面文案中的「授权」是否统一替换？ -> A: 全部界面文案的「授权」改为「鉴权」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 桌面端点击鉴权链接打开鉴权页 (Priority: P1)

桌面应用用户在配置面板点击鉴权链接，宿主按自身外链行为打开鉴权页；用户完成登录后回到应用，面板显示已鉴权。

**Why this priority**: 当前桌面端点击没有任何反馈，鉴权无法开始，OAuth 服务器上的全部工具都不可用。

**Independent Test**: 在桌面应用中为待鉴权 OAuth 服务器点击鉴权链接，确认鉴权页可见；完成登录后确认面板显示已鉴权。

**Acceptance Scenarios**:

1. **Given** 桌面应用中有待鉴权的 OAuth 服务器，**When** 用户点击鉴权链接，**Then** 宿主打开该服务器的鉴权页。
2. **Given** 鉴权页已打开，**When** 用户完成登录并回调，**Then** 面板显示该服务器已鉴权且工具可用。
3. **Given** 鉴权链接的地址对宿主可用，**When** 用户用键盘激活链接，**Then** 结果与鼠标点击一致。

---

### User Story 2 - 鉴权入口改为操作行下方的文字链接 (Priority: P1)

待鉴权时，鉴权入口不再出现在操作按钮行，而是在该行下方单独显示：「点击鉴权」文字与完整地址链接。

**Why this priority**: 桌面端按钮行中的鉴权操作不可用；改为链接后由宿主处理打开行为，入口也更明确。

**Independent Test**: 构造一台待鉴权服务器与一台已鉴权服务器，检查鉴权行的位置、内容、字号与颜色。

**Acceptance Scenarios**:

1. **Given** 一台 OAuth 服务器待鉴权，**When** 用户查看该服务器行，**Then** 操作按钮行下方显示鉴权行，内容为「点击鉴权」文字与完整地址链接。
2. **Given** 鉴权行已显示，**When** 用户查看排版，**Then** 字号与服务器简介一致，颜色使用宿主警告色。
3. **Given** 一台服务器已鉴权，**When** 用户查看该服务器行，**Then** 操作按钮行中不出现鉴权按钮，也不显示鉴权行。
4. **Given** 鉴权行在窄面板中显示，**When** 地址超出可用宽度，**Then** 地址换行显示且不撑破布局。

---

### User Story 3 - web 端鉴权体验保持可用 (Priority: P1)

web profile 用户使用同一鉴权入口，鉴权页按宿主行为打开，回调与面板状态保持现有结果。

**Why this priority**: 修复桌面端不得回归 web 端已经验证通过的流程。

**Independent Test**: 在 web profile 中完成一次鉴权，确认入口位置、鉴权页打开与回调结果。

**Acceptance Scenarios**:

1. **Given** web profile 中存在待鉴权 OAuth 服务器，**When** 用户点击鉴权链接，**Then** 鉴权页按宿主默认外链行为打开。
2. **Given** 鉴权完成，**When** 回调页返回，**Then** 面板状态与回调页行为保持现有结果。

---

### User Story 4 - 完整地址可见可复制 (Priority: P2)

用户看到并复制鉴权链接的完整地址，粘贴到其他窗口仍能进入鉴权页。

**Why this priority**: 复制地址可用于排查，也是地址完整性的直接检验。

**Independent Test**: 在桌面端与 web 端分别复制鉴权行的地址，粘贴到浏览器地址栏，确认进入鉴权页。

**Acceptance Scenarios**:

1. **Given** 待鉴权服务器显示鉴权行，**When** 用户复制链接地址，**Then** 地址是可直接访问的完整地址。
2. **Given** 已复制的鉴权地址，**When** 用户在其他窗口打开它，**Then** 进入鉴权页并进入等待回调状态。

---

### Edge Cases

- 宿主重启后端口变化：面板刷新后鉴权行显示当前完整地址。
- 用户在鉴权过程中重复点击：允许再次打开鉴权页，回调只更新发起本次鉴权的服务器。
- 鉴权启动失败：鉴权页显示失败原因，面板保留可再次点击的鉴权链接。
- 鉴权页打开期间服务器被删除或改名：回调不得把鉴权结果写入其他服务器。
- 用户已在另一窗口完成鉴权：面板在状态刷新后显示已鉴权，鉴权行消失。
- 用户关闭鉴权页而未完成登录：面板保留待鉴权状态，鉴权行继续可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 以 a 标签呈现鉴权入口，并把点击交给宿主的外链行为处理。
- **FR-002**: System MUST 从操作按钮行移除鉴权与重新鉴权操作。
- **FR-003**: System MUST 在待鉴权服务器的操作按钮行下方显示鉴权行，内容为「点击鉴权」文字与完整地址链接。
- **FR-004**: System MUST 让鉴权行的字号与服务器简介一致。
- **FR-005**: System MUST 让鉴权行使用宿主警告色。
- **FR-006**: System MUST 让鉴权行在完整地址可用后才渲染。
- **FR-007**: System MUST 提供可被宿主外链行为接受的完整绝对地址，桌面端与 web 端行为一致。
- **FR-008**: System MUST 保留链接地址的键盘激活与复制能力。
- **FR-009**: System MUST 保持 web profile 的回调与面板结果不变。
- **FR-010**: System MUST 保证一次鉴权回调只更新发起该次鉴权的服务器。
- **FR-011**: System MUST 在鉴权完成后按现有行为关闭成功回调页并刷新面板。
- **FR-012**: System MUST 保持无需 OAuth 的服务器与其他面板操作行为不变。
- **FR-013**: System MUST 在宿主地址变化后显示当前完整地址。
- **FR-014**: System MUST 把界面可见文案中的「授权」统一改为「鉴权」。
- **FR-015**: System MUST 在服务器已鉴权时不显示鉴权行；重新登录通过退出登录后再次鉴权完成。

### Key Entities

- **鉴权链接**: 指向一次鉴权流程的完整地址，只在待鉴权时出现，可点击、可复制、可由键盘激活。
- **鉴权行**: 服务器操作按钮行下方的一行内容，包含「点击鉴权」文字与完整地址链接。
- **MCP 服务器**: 具有连接方式、OAuth 要求、鉴权状态与连接状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在桌面应用中，待鉴权服务器从点击鉴权链接到鉴权页可见的成功率为 100%。
- **SC-002**: 桌面端上鉴权链接的可见点击反馈时延低于 1 秒。
- **SC-003**: web profile 的鉴权流程回归通过率为 100%，回调与面板结果与修复前一致。
- **SC-004**: 复制鉴权行地址后可直接访问的比例为 100%。
- **SC-005**: 鉴权行出现在操作按钮行下方的比例为 100%，鉴权操作出现在按钮行中的次数为 0。
- **SC-006**: 鉴权行字号与服务器简介一致、颜色为宿主警告色的检查通过率为 100%。
- **SC-007**: 完整地址可用前渲染鉴权行的次数为 0。
- **SC-008**: 一次鉴权回调只更新其所属服务器，跨服务器写错次数为 0。
- **SC-009**: 界面可见文案中「授权」出现次数为 0。

## Assumptions

- 桌面端宿主把 a 标签的完整 http/https 地址交给系统默认浏览器，同源相对地址不触发外链。
- 插件注册的鉴权启动地址可以被系统浏览器直接访问。
- 完整地址取自宿主服务器的当前地址，面板每次刷新后随之更新。
- 鉴权服务器发现、客户端注册与凭据存储保持现有实现。
- 现有面板的其他操作、会话可见性与凭据存储行为保持不变。
