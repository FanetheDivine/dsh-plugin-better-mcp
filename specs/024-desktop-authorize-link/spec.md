## User Scenarios & Testing *(mandatory)*

### User Story 1 - 桌面端点击授权打开授权页 (Priority: P1)

桌面应用用户在配置面板点击授权链接，宿主按自身外链行为打开授权页；用户完成登录后回到应用，面板显示已授权。

**Why this priority**: 当前桌面端点击没有任何反馈，授权无法开始，OAuth 服务器上的全部工具都不可用。

**Independent Test**: 在桌面应用中为待授权 OAuth 服务器点击授权链接，确认授权页可见；完成登录后确认面板显示已授权。

**Acceptance Scenarios**:

1. **Given** 桌面应用中有待授权的 OAuth 服务器，**When** 用户点击授权链接，**Then** 宿主打开该服务器的授权页。
2. **Given** 授权页已打开，**When** 用户完成登录并回调，**Then** 面板显示该服务器已授权且工具可用。
3. **Given** 授权链接的地址对宿主可用，**When** 用户用键盘激活链接，**Then** 结果与鼠标点击一致。

---

### User Story 2 - 授权入口改为操作行下方的文字链接 (Priority: P1)

待授权时，授权入口不再出现在操作按钮行，而是在该行下方单独显示：「点击授权」文字与完整地址链接。

**Why this priority**: 桌面端按钮行中的授权操作不可用；改为链接后由宿主处理打开行为，入口也更明确。

**Independent Test**: 构造一台待授权服务器与一台已授权服务器，检查授权行的位置、内容、字号与颜色。

**Acceptance Scenarios**:

1. **Given** 一台 OAuth 服务器待授权，**When** 用户查看该服务器行，**Then** 操作按钮行下方显示授权行，内容为「点击授权」文字与完整地址链接。
2. **Given** 授权行已显示，**When** 用户查看排版，**Then** 字号与服务器简介一致，颜色使用宿主警告色。
3. **Given** 一台服务器已授权，**When** 用户查看该服务器行，**Then** 操作按钮行中不出现授权按钮。
4. **Given** 授权行在窄面板中显示，**When** 地址超出可用宽度，**Then** 地址换行显示且不撑破布局。

---

### User Story 3 - web 端授权体验保持可用 (Priority: P1)

web profile 用户使用同一授权入口，授权页按宿主行为打开，回调与面板状态保持现有结果。

**Why this priority**: 修复桌面端不得回归 web 端已经验证通过的流程。

**Independent Test**: 在 web profile 中完成一次授权，确认入口位置、授权页打开与回调结果。

**Acceptance Scenarios**:

1. **Given** web profile 中存在待授权 OAuth 服务器，**When** 用户点击授权链接，**Then** 授权页按宿主默认外链行为打开。
2. **Given** 授权完成，**When** 回调页返回，**Then** 面板状态与回调页行为保持现有结果。

---

### User Story 4 - 完整地址可见可复制 (Priority: P2)

用户看到并复制授权链接的完整地址，粘贴到其他窗口仍能进入授权页。

**Why this priority**: 复制地址可用于排查，也是地址完整性的直接检验。

**Independent Test**: 在桌面端与 web 端分别复制授权行的地址，粘贴到浏览器地址栏，确认进入授权页。

**Acceptance Scenarios**:

1. **Given** 待授权服务器显示授权行，**When** 用户复制链接地址，**Then** 地址是可直接访问的完整地址。
2. **Given** 已复制的授权地址，**When** 用户在其他窗口打开它，**Then** 进入授权页并进入等待回调状态。

---

### Edge Cases

- 宿主重启后端口变化：面板刷新后授权行显示当前完整地址。
- 用户在授权过程中重复点击：允许再次打开授权页，回调只更新发起本次授权的服务器。
- 授权启动失败：授权页显示失败原因，面板保留可再次点击的授权链接。
- 授权页打开期间服务器被删除或改名：回调不得把授权结果写入其他服务器。
- 用户已在另一窗口完成授权：面板在状态刷新后显示已授权，授权行消失。
- 用户关闭授权页而未完成登录：面板保留待授权状态，授权行继续可用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 以 a 标签呈现授权入口，并把点击交给宿主的外链行为处理。
- **FR-002**: System MUST 从操作按钮行移除授权与重新授权操作。
- **FR-003**: System MUST 在待授权服务器的操作按钮行下方显示授权行，内容为「点击授权」文字与完整地址链接。
- **FR-004**: System MUST 让授权行的字号与服务器简介一致。
- **FR-005**: System MUST 让授权行使用宿主警告色。
- **FR-006**: System MUST 让授权行在完整地址可用后才渲染。
- **FR-007**: System MUST 提供可被宿主外链行为接受的完整绝对地址，桌面端与 web 端行为一致。
- **FR-008**: System MUST 保留链接地址的键盘激活与复制能力。
- **FR-009**: System MUST 保持 web profile 的回调与面板结果不变。
- **FR-010**: System MUST 保证一次授权回调只更新发起该次授权的服务器。
- **FR-011**: System MUST 在授权完成后按现有行为关闭成功回调页并刷新面板。
- **FR-012**: System MUST 保持无需 OAuth 的服务器与其他面板操作行为不变。
- **FR-013**: System MUST 在宿主地址变化后显示当前完整地址。

### Key Entities

- **授权链接**: 指向一次授权流程的完整地址，只在待授权时出现，可点击、可复制、可由键盘激活。
- **授权行**: 服务器操作按钮行下方的一行内容，包含「点击授权」文字与授权链接。
- **MCP 服务器**: 具有连接方式、OAuth 要求、授权状态与连接状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在桌面应用中，待授权服务器从点击授权链接到授权页可见的成功率为 100%。
- **SC-002**: 桌面端上授权链接的可见点击反馈时延低于 1 秒。
- **SC-003**: web profile 的授权流程回归通过率为 100%，回调与面板结果与修复前一致。
- **SC-004**: 复制授权行地址后可直接访问的比例为 100%。
- **SC-005**: 授权行出现在操作按钮行下方的比例为 100%，授权操作出现在按钮行中的次数为 0。
- **SC-006**: 授权行字号与服务器简介一致、颜色为宿主警告色的检查通过率为 100%。
- **SC-007**: 完整地址可用前渲染授权行的次数为 0。
- **SC-008**: 一次授权回调只更新其所属服务器，跨服务器写错次数为 0。

## Assumptions

- 桌面端宿主把 a 标签的完整 http/https 地址交给系统默认浏览器，同源相对地址不触发外链。
- 插件注册的授权启动地址可以被系统浏览器直接访问。
- 完整地址取自宿主服务器的当前地址，面板每次刷新后随之更新。
- 授权服务器发现、客户端注册与凭据存储保持现有实现。
- 现有面板的其他操作、会话可见性与凭据存储行为保持不变。
