# Feature Specification: MCP 状态与会话同步

**Feature Branch**: `fix/018-mcp-state-sync`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "配置 MCP 后，弹窗应持续显示最新连接状态；MCP 变化后，需要向会话注入 system-reminder 消息。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 弹窗持续显示连接结果 (Priority: P1)

用户在 MCP 弹窗中保存服务器配置后，保持弹窗打开即可看到连接中、连接成功或失败等最新状态，以及对应的工具数、时间或错误信息。

**Why this priority**: 连接结果决定用户能否继续使用服务器。状态停滞会让用户误判配置结果，并增加重复操作。

**Independent Test**: 打开弹窗并保存一个可控制连接结果的服务器，观察从连接到最终状态的全过程，全程保持弹窗打开且不手动刷新。

**Acceptance Scenarios**:

1. **Given** 弹窗已打开且用户保存了有效配置，**When** 服务器随后连接成功，**Then** 弹窗自动显示连接成功及最新工具信息。
2. **Given** 弹窗已打开且服务器正在连接，**When** 服务器连接失败或进入重连，**Then** 弹窗自动显示对应状态和可用诊断信息。
3. **Given** 用户关闭了弹窗，**When** 服务器状态继续变化，**Then** 再次打开弹窗时直接显示当前状态。

---

### User Story 2 - 会话及时获知 MCP 变化 (Priority: P2)

用户修改 MCP 配置或会话内服务器可见性后，相关会话收到包含最新 MCP 目录的 system-reminder 消息，后续模型步骤使用该目录。

**Why this priority**: 模型需要知道当前可用的服务器及工具范围，才能正确使用变化后的 MCP 能力。

**Independent Test**: 在已有会话中修改服务器配置或可见性，检查该会话的消息记录，并验证下一次模型步骤能读到最新目录。

**Acceptance Scenarios**:

1. **Given** 至少一个会话已经打开，**When** 一次 MCP 配置变化生效，**Then** 每个在线会话收到一条反映最新目录的 system-reminder 消息。
2. **Given** 一个会话改变了某台服务器的可见性，**When** 变化生效，**Then** 该会话收到反映最新可见性的 system-reminder 消息。
3. **Given** 会话已经收到某次变化的目录，**When** 后续操作没有产生有效目录变化，**Then** 会话保持现有目录消息，避免重复通知。

### Edge Cases

- 连续发生多次状态变化时，弹窗显示最新状态，较早请求的延迟结果不能覆盖它。
- 状态刷新失败时，弹窗保留最近成功快照并显示可重试的错误。
- 配置保存失败或校验失败时，会话目录保持不变。
- 连续发生多次配置变化时，通知可以合并，后续模型步骤以最新目录为准。
- 删除最后一台服务器后，已发布过目录的在线会话收到空目录通知。
- 变化期间离线的会话在下次使用时获得当前完整目录。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 弹窗打开期间 MUST 自动更新所有受管服务器的连接状态和相关元数据。
- **FR-002**: 弹窗 MUST 在服务器进入最终连接状态后 2 秒内显示该状态。
- **FR-003**: 弹窗 MUST 保证并发或延迟的刷新结果按实际状态顺序呈现。
- **FR-004**: 弹窗关闭期间 MUST 停止自动刷新，重新打开时 MUST 读取当前完整快照。
- **FR-005**: MCP 服务器新增、编辑、删除或可见性变化生效后，系统 MUST 向受影响的在线会话注入 system-reminder 目录消息。
- **FR-006**: 目录消息 MUST 包含变化生效后的完整服务器目录及每台服务器在该会话中的可见性。
- **FR-007**: 目录消息 MUST 持久化在会话记录中，并在后续模型步骤前可见。
- **FR-008**: 系统 MUST 抑制没有产生有效目录变化的重复通知。
- **FR-009**: 连续变化产生的通知 MAY 合并，最终通知 MUST 反映最新目录。

### Key Entities *(include if feature involves data)*

- **服务器状态快照**: 一台服务器在某一时刻的连接状态、工具数、连接时间、尝试次数和诊断信息。
- **会话目录消息**: 面向一个会话的 system-reminder，记录完整服务器目录、可见性及对应变化。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 的连接成功、连接失败和重连测试在状态变化后 2 秒内反映到已打开的弹窗。
- **SC-002**: 用户保持弹窗打开即可完成连接结果确认，手动刷新和重新打开弹窗的验证用例结果一致。
- **SC-003**: 100% 的有效 MCP 配置和可见性变化在下一次模型步骤前写入受影响会话。
- **SC-004**: 100% 的有效变化被受影响会话的最新目录通知覆盖，无变化操作产生的重复通知数为 0。
- **SC-005**: 连续变化测试中，最终弹窗状态和会话目录均与最后一次生效状态一致。

## Assumptions

- MCP 变化包括本插件管理的服务器配置变化和每个会话的服务器可见性变化。
- 连接状态变化用于面板展示；会话目录描述服务器及其可见性。
- 在线会话在变化生效时接收通知；离线会话沿用恢复时的完整目录机制。
- 连续变化的通知可以合并，会话记录保留已注入的通知，模型以最新通知为准。
