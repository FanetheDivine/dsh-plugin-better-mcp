# Quickstart: MCP 状态与会话同步

## 准备

1. 安装依赖：`pnpm install --frozen-lockfile`。
2. 使用与 `@deepseek-ai/dsh-agent@0.2.2-rc.3` 相同的 DSH 发布做实机验证。
3. 准备两个可控制连接结果的 MCP 服务器，以及至少两个会话。

## 自动化验证

```sh
pnpm test:code --reporter=verbose
pnpm full-check
```

重点覆盖：

- 面板立即读取、1 秒串行刷新、慢请求不重叠、卸载停止刷新。
- 延迟响应不能覆盖较新的快照。
- 配置变化注入全部在线会话，可见性变化只注入调用方会话。
- 无变化操作去重，连续变化在下一步只保留最新目录。
- 删除最后一台服务器后注入空目录。

## 实机验证

按 `real-device-test` skill 建专用 profile 并加载本分支构建产物。

1. 打开 MCP 弹窗，新增一个会延迟连接的服务器。
2. 保持弹窗打开，确认 2 秒内显示连接成功及工具数。
3. 使用失败端点重连，确认弹窗自动显示失败或重连状态。
4. 关闭弹窗后再打开，确认直接显示当前状态。
5. 打开两个会话，修改服务器简介，确认两个会话都记录目录通知。
6. 在一个会话调用 `mcp_manage`，确认另一个会话的目录保持不变。
7. 连续修改配置后发送下一条消息，确认模型只看到最新完整目录。

字段与消息结构见 [data-model.md](./data-model.md)。
