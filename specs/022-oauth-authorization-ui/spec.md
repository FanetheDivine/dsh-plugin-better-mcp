# Feature Specification: OAuth 授权与待授权提示

**Feature Branch**: `fix/022-oauth-authorization-ui`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "修复 Figma MCP 因客户端不存在而授权失败；OAuth 直接展示在配置面板；授权入口使用 a 标签并遵循 DSH 默认外链行为；高亮授权按钮；有待授权 MCP 时高亮侧边栏图标并增加阴影呼吸动效；未授权 MCP 不写入会话目录提醒，授权成功后立即发送一条提醒。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完成 Figma 授权 (Priority: P1)

用户在插件中配置 Figma 官方 MCP 后，从配置面板发起授权并完成登录。授权过程使用 Figma 当前接受的客户端身份，避免出现客户端不存在的错误。

**Why this priority**: 授权失败会阻止用户使用 Figma 的全部工具。

**Independent Test**: 使用 Figma 官方 MCP 地址发起授权，在浏览器完成登录，确认回调后服务器已授权且工具可用。

**Acceptance Scenarios**:

1. **Given** Figma 官方 MCP 尚未授权，**When** 用户点击授权链接，**Then** 系统使用 Figma 接受的客户端身份发起授权，且页面不出现客户端不存在错误。
2. **Given** Figma 授权页已打开，**When** 用户同意访问并完成回调，**Then** 配置面板显示已授权，服务器可以连接。
3. **Given** 授权启动失败，**When** 授权页收到结果，**Then** 授权页显示具体原因，配置面板保留重试入口。

---

### User Story 2 - 从配置面板直接授权 (Priority: P1)

用户在配置面板查看需要 OAuth 的服务器，并通过清晰可见的授权链接直接进入外部授权页。链接遵循 DSH 的默认外链打开行为。

**Why this priority**: 授权是服务器可用的必要步骤，入口应位于用户配置服务器的位置。

**Independent Test**: 在配置面板定位待授权服务器，检查授权入口为链接并点击，确认由 DSH 默认行为打开授权页。

**Acceptance Scenarios**:

1. **Given** 配置面板中存在待授权服务器，**When** 用户查看该服务器，**Then** 授权操作直接可见且使用高亮样式。
2. **Given** 授权链接已经获得授权地址，**When** 用户点击链接，**Then** 系统按 DSH 默认外链行为打开窗口。
3. **Given** 用户通过键盘操作配置面板，**When** 焦点移动到授权链接并激活，**Then** 行为与鼠标点击一致。
4. **Given** 授权地址尚未就绪，**When** 用户查看授权区域，**Then** 系统显示可理解的准备状态，且不产生无效导航。

---

### User Story 3 - 会话目录仅列出可用服务器 (Priority: P1)

用户只应在会话的系统提醒中看到当前已授权可用的 MCP。未授权服务器必须被排除；一旦授权成功，系统提醒应立即更新，使后续模型步骤可以发现并使用该服务器。

**Why this priority**: 把未授权服务器写入提醒会误导模型调用不可用的工具，造成错误和无效步骤。

**Independent Test**: 构造未授权与已授权服务器，检查 `catalogFor` 生成的条目；模拟授权成功后确认在线 Agent 立即收到包含该服务器的更新提醒。

**Acceptance Scenarios**:

1. **Given** 一台 OAuth 服务器尚未授权，**When** 系统为 Agent 生成会话目录提醒，**Then** 提醒的目录中不包含该服务器。
2. **Given** 同一台服务器在上一轮提醒中缺席，**When** 用户成功授权，**Then** 该 Agent 立即收到一条包含该服务器的新目录提醒。
3. **Given** 一台无需 OAuth 的 stdio 服务器，**When** 系统生成会话目录提醒，**Then** 它按现有规则出现。
4. **Given** 用户退出登录，**When** 下一次目录提醒生成，**Then** 该服务器被排除，旧目录不再误导模型。

---

### User Story 4 - 识别待授权服务器 (Priority: P2)

用户在插件其他区域或宿主侧边栏中，无需逐台检查服务器即可发现存在待授权 MCP。

**Why this priority**: 明确的全局提示能引导用户及时完成授权，减少工具不可用的困惑。

**Independent Test**: 分别构造全部已授权、存在待授权、没有 OAuth 服务器三种状态，检查授权按钮与侧边栏图标的视觉状态。

**Acceptance Scenarios**:

1. **Given** 至少一台 OAuth 服务器待授权，**When** 宿主显示插件侧边栏入口，**Then** 图标高亮并显示阴影呼吸动效。
2. **Given** 所有 OAuth 服务器均已授权，**When** 宿主显示插件侧边栏入口，**Then** 图标恢复常规样式且停止待授权动效。
3. **Given** 用户启用减少动态效果偏好，**When** 存在待授权服务器，**Then** 图标保持高亮且不使用持续呼吸动效。
4. **Given** 多台服务器同时待授权，**When** 其中一台完成授权，**Then** 全局提示在其他服务器完成授权前保持有效。

### User Story 5 - 完成授权后关闭回调页 (Priority: P1)

用户完成授权后回到工作界面，无需手动关闭回调标签页。

**Independent Test**: 完成一次成功授权与一次失败授权，检查成功页请求关闭，失败页保留错误信息。

### User Story 6 - 选择 OAuth 客户端身份 (Priority: P1)

用户可以选择 DSH 或 Codex 动态注册身份，默认使用 Codex。选中项只显示名称，Codex 选项提供身份说明；选择 DSH 时可通过帮助提示了解服务器身份限制。

**Independent Test**: 分别选择两种身份并保存，检查选中标签、选项说明、帮助提示和实际注册身份。

### User Story 7 - 图标自身呈现呼吸阴影 (Priority: P2)

待授权阴影围绕侧边栏 SVG 图标呈现，按钮背景保持透明。

**Independent Test**: 在折叠与展开侧边栏中检查图标投影，确认按钮没有呼吸背景或外扩方形阴影。

### Edge Cases

- 服务器在授权过程中被删除或修改时，回调不得把授权结果关联到另一台服务器。
- 授权链接失效或授权状态过期时，用户可以重新获取链接并重试。
- 授权状态刷新失败时，面板保留上次确定的状态并显示错误，不错误宣告授权成功。
- 没有 OAuth 服务器或全部服务器均已授权时，不显示待授权全局提示。
- 禁用动画时，待授权状态仍有静态视觉提示。
- 目录提醒生成期间服务器状态同时变化时，以生成时刻的授权快照为准；下一次提醒继续收敛到最新状态。
- 浏览器阻止脚本关窗时，成功回调页保留完成提示。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 支持用户使用 Figma 官方 MCP 完成 OAuth 授权，且不使用 Figma 已不接受的客户端身份。
- **FR-002**: System MUST 在 OAuth 启动失败时显示失败原因与可用重试入口。
- **FR-003**: System MUST 在配置面板直接展示每台待授权服务器的授权操作。
- **FR-004**: System MUST 将授权操作渲染为具有真实目标地址的链接，并遵循 DSH 默认外链行为。
- **FR-005**: System MUST 允许用户通过鼠标与键盘激活授权链接。
- **FR-006**: System MUST 高亮待授权服务器的授权操作，使其区别于普通次要操作。
- **FR-007**: System MUST 在至少一台 OAuth 服务器待授权时高亮插件侧边栏图标，并显示阴影呼吸动效。
- **FR-008**: System MUST 在没有待授权服务器时移除侧边栏待授权高亮与动效。
- **FR-009**: System MUST 在用户偏好减少动态效果时停用持续呼吸动效，同时保留静态高亮。
- **FR-010**: System MUST 根据全部服务器的实时授权状态更新待授权提示。
- **FR-011**: System MUST 保证授权回调只更新发起该次授权的服务器。
- **FR-012**: System MUST 保持现有无需 OAuth 的服务器配置与连接行为。
- **FR-013**: System MUST 从注入会话的 MCP 目录提醒中排除尚未授权的 OAuth 服务器。
- **FR-014**: System MUST 在 OAuth 授权成功后立即向受影响在线 Agent 发送包含该服务器的目录更新提醒。
- **FR-015**: System MUST 在退出登录后的下一次目录提醒中排除对应服务器。
- **FR-016**: System MUST 保持无需 OAuth 的服务器在会话目录中的现有显示规则。
- **FR-017**: System MUST 在授权成功回调页请求浏览器关闭当前标签页，失败页保留错误信息。
- **FR-018**: System MUST 提供 DSH 与 Codex 两种动态注册身份，默认 Codex，并把选择用于实际客户端注册。
- **FR-019**: System MUST 让选中项仅显示 DSH 或 Codex，Codex 选项显示连接身份说明，DSH 状态提供服务器身份限制提示。
- **FR-020**: System MUST 将待授权呼吸阴影应用于侧边栏 SVG 图标，按钮背景保持透明。

### Key Entities

- **MCP 服务器**: 具有连接方式、OAuth 要求、授权状态与连接状态。
- **授权链接**: 指向一次授权流程的目标地址，具有准备中、可打开与失效状态。
- **待授权提示**: 汇总全部 MCP 服务器的授权状态，驱动授权操作与侧边栏入口的视觉状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用受支持的 Figma 官方 MCP 配置时，用户可以在一次授权尝试中进入有效授权页，客户端不存在错误发生率为 0。
- **SC-002**: 用户从配置面板发起授权所需的主要操作不超过 2 次点击。
- **SC-003**: 100% 的待授权服务器在配置面板中直接显示高亮授权链接。
- **SC-004**: 授权状态变化后，配置面板与侧边栏提示在 2 秒内保持一致。
- **SC-005**: 在全部已授权、部分待授权、无 OAuth 服务器三类测试中，待授权提示判断准确率为 100%。
- **SC-006**: 键盘用户可以定位并激活全部授权链接，且不依赖鼠标专属操作。
- **SC-007**: 未授权 OAuth 服务器出现在会话目录提醒中的次数为 0；授权成功后在线 Agent 在 2 秒内收到新目录。
- **SC-008**: 支持脚本关窗的浏览器中，成功回调页自动关闭；失败页信息保留率为 100%。
- **SC-009**: 两种身份的界面选择与保存后的实际注册身份一致率为 100%。

## Assumptions

- Figma 官方 MCP 地址为 `https://mcp.figma.com/mcp`。
- Figma 当前至少接受一种无需用户自建 OAuth 应用的客户端身份。
- DSH 默认外链行为负责在默认浏览器中打开授权页。
- 本次范围包括配置面板与插件侧边栏入口，不 redesign 其他插件页面。
- 现有服务器增删改、会话可见性与凭据存储行为保持不变。
