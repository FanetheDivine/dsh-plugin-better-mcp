# Feature Specification: 按会话管理 MCP 可见性

**Feature Branch**: `feat/015-mcp-visibility`

**Created**: 2026-11-18

**Status**: Draft

**Input**: User description: "1. 彻底移除将插件的 tools 聚合为 MCP 的能力。2. locale/zh.json 描述改为「可视化地对MCP进行管理和鉴权；提供MCP懒加载能力」。3. 工具只提供 mcp_manage({server, command: 'active'|'inactive'})，用于模型控制哪些 MCP 可见。4. 可见的 MCP tools 加入模型的工具集，由模型直接调用，不再通过 mcp_call 间接调用。5. 用户配置 MCP 时要配置简介。6. 向会话写 system-reminder，向模型说明可用的 MCP 名称和简介，并说明通过 mcp_manage 管理可见性；确保至少有一条这种消息，因为会话可能压缩。7. MCP 可见性变化时写一条 system-reminder 告知模型，说明可以使用前缀为 mcp__xxx__ 的 tool。8. 修改审查中发现的问题。"

## Clarifications

### Session 2026-11-18

- Q: 可见性作用于哪里？ → A: 服务器始终挂载；可见性指当前会话是否注入该服务器的工具。
- Q: 配置里的 lazy 与可见性如何关系？ → A: lazy 表示默认不可见。
- Q: 其他插件或设置页挂载的 MCP 服务器如何处理？ → A: 不纳入 mcp_manage 与提醒；面板只读显示其状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 模型按会话控制 MCP 可见性 (Priority: P1)

用户配置了多台 MCP 服务器。每个会话开始时，只有非懒加载服务器的工具出现在模型的工具集里。模型调用 `mcp_manage` 把某台服务器设为 `active`，从下一步起该服务器的工具直接出现在本会话的工具集，模型直接调用它们。设为 `inactive` 后，工具从本会话的工具集移除。其他会话的工具集不受影响。

**Why this priority**: 多台服务器的工具同时注入会挤占上下文；按会话按需注入是本插件的核心价值。

**Independent Test**: 配置一台懒加载服务器和一台非懒加载服务器。新会话里只看到非懒加载服务器的工具。模型调用 `mcp_manage` 激活懒加载服务器后，下一步出现其工具并可直接调用。另一个会话的工具集保持不变。

**Acceptance Scenarios**:

1. **Given** 服务器 A 为懒加载、B 为非懒加载且都已连接，**When** 新会话开始第一步，**Then** 工具集包含 B 的工具，不含 A 的工具。
2. **Given** 会话 1 中 A 不可见，**When** 模型调用 `mcp_manage({ server: 'A', command: 'active' })`，**Then** 工具返回成功，会话 1 下一步的工具集包含 A 的全部工具。
3. **Given** 会话 1 中 A 可见，会话 2 中 A 不可见，**When** 会话 2 进入下一步，**Then** 会话 2 的工具集仍不含 A 的工具。
4. **Given** 会话 1 中 B 可见，**When** 模型调用 `mcp_manage({ server: 'B', command: 'inactive' })`，**Then** 会话 1 下一步的工具集不含 B 的工具。
5. **Given** 模型传入未配置的服务器名或非法 `command`，**When** 调用 `mcp_manage`，**Then** 工具返回错误，列出可用服务器名，本会话可见性不变。
6. **Given** 插件启用，**When** 宿主启动完成，**Then** 本插件配置的全部服务器都挂载，与懒加载设置无关。

### User Story 2 - 会话内 MCP 目录提醒 (Priority: P1)

模型需要知道有哪些 MCP 服务器、各自做什么、当前是否可见，以及如何切换。插件在会话中写入一条 system-reminder 目录消息，列出本插件配置的每台服务器的名称、简介与本会话的可见性，并说明用 `mcp_manage` 切换可见性。会话压缩后，如果模型看到的上下文里已没有目录消息，插件在下一步补写一条。可见性变化时，插件写一条更新消息，说明哪些服务器变为可见或不可见，并告知可见服务器的工具以 `mcp__<server>__` 为前缀。

**Why this priority**: 没有目录消息，模型不知道懒加载服务器存在，`mcp_manage` 无法被正确使用。

**Independent Test**: 新会话第一步的上下文包含目录消息。触发压缩后，下一步的上下文重新出现目录消息。调用 `mcp_manage` 激活服务器后，下一步出现一条更新消息，包含 `mcp__<server>__` 前缀说明。

**Acceptance Scenarios**:

1. **Given** 本插件配置了至少一台服务器，**When** 会话第一步开始，**Then** 模型上下文包含一条目录消息，列出每台服务器的名称、简介与可见性，并说明 `mcp_manage` 的用法。
2. **Given** 目录消息已在模型可见的上下文里且内容未变，**When** 会话进入下一步，**Then** 插件不写新消息。
3. **Given** 会话压缩移除了全部目录消息，**When** 会话进入下一步，**Then** 插件补写一条反映当前状态的目录消息。
4. **Given** 模型激活服务器 A，**When** 会话进入下一步，**Then** 插件写一条更新消息，说明 A 已可见，其工具以 `mcp__A__` 为前缀，可直接调用。
5. **Given** 模型停用服务器 A，**When** 会话进入下一步，**Then** 插件写一条更新消息，说明 A 已不可见，模型不应再调用 `mcp__A__` 前缀的工具。
6. **Given** 用户新增、删除服务器或修改简介，**When** 任一会话进入下一步，**Then** 该会话收到反映新目录的更新消息。
7. **Given** 本插件没有配置任何服务器且会话从未收到目录消息，**When** 会话进入下一步，**Then** 插件不写消息。

### User Story 3 - 配置服务器简介 (Priority: P2)

用户新增或编辑服务器时必须填写简介。简介出现在目录消息里，帮助模型判断何时激活该服务器。

**Why this priority**: 目录消息依赖简介；没有简介，模型只能凭名称猜测用途。

**Independent Test**: 在面板新增服务器时不填简介，保存被拒绝并提示原因。填写简介保存后，新会话的目录消息包含该简介。

**Acceptance Scenarios**:

1. **Given** 用户打开新增表单，**When** 简介为空并点保存，**Then** 表单显示「简介必填」的提示，不提交。
2. **Given** 用户填写简介并保存，**When** 新会话开始，**Then** 目录消息中该服务器的简介与用户填写的一致。
3. **Given** 配置文件里某服务器缺少简介，**When** 插件读取配置，**Then** 插件报告该字段缺失的配置错误。

---

### User Story 4 - 移除工具聚合端点 (Priority: P1)

插件不再把宿主工具聚合为 HTTP MCP 端点。端点路由、端点令牌、`expose` 配置与面板里的端点区块全部移除。`mcp_call` 与 `mcp_servers` 工具同时移除。

**Why this priority**: 用户判定该能力不合理，保留会带来安全面与维护成本。

**Independent Test**: 启用插件后，原端点路径返回宿主默认的未找到响应。面板没有端点区块。工具表里没有 `mcp_call` 与 `mcp_servers`。配置含 `expose` 时插件报告未知配置键。

**Acceptance Scenarios**:

1. **Given** 插件启用，**When** 外部客户端请求原端点路径，**Then** 插件不处理该请求。
2. **Given** 用户打开面板，**Then** 面板只显示服务器列表与操作。
3. **Given** 模型的工具集，**Then** 本插件只提供 `mcp_manage`。

---

### User Story 5 - 文案与面板修正 (Priority: P2)

插件的元数据与面板文案一致、可翻译，面板只提供能成功的操作。

**Why this priority**: 审查发现的文案与交互问题直接影响用户理解。

**Independent Test**: 切换中英文，逐项核对插件页与面板文案全部随语言切换，按钮语义正确。

**Acceptance Scenarios**:

1. **Given** 中文界面，**Then** 插件描述为「可视化地对MCP进行管理和鉴权；提供MCP懒加载能力」；英文界面显示对应译文。
2. **Given** 面板头部，**Then** 只显示一个标题，刷新按钮的文案为「刷新」。
3. **Given** 服务器行，**Then** 连接状态、状态说明、工具数与认证方式选项都随语言切换。
4. **Given** 其他插件挂载的服务器行，**Then** 面板不显示重连、编辑、删除等操作。
5. **Given** 英文界面，**Then** 徽标与开关文案使用 sentence case。

### Edge Cases

- 激活的服务器尚未连接、需要授权或连接失败：`mcp_manage` 仍记录可见，返回当前连接状态与原因；连接成功后工具自动出现在该会话。
- 服务器重连或工具列表变化：可见会话的工具集随之更新，不可见会话仍不含其工具。
- 用户删除一台服务器：所有会话的可见性记录中忽略该服务器，下一步收到更新消息。
- 用户切换某服务器的懒加载设置：只影响尚未用 `mcp_manage` 显式切换过该服务器的会话。
- 同一步内多次调用 `mcp_manage`：以最后一次为准，下一步只写一条更新消息。
- 子代理会话：拥有独立的可见性与目录消息。
- 会话恢复：可见性从会话历史恢复，与恢复前一致。
- 服务器名与其他插件的服务器冲突：保存被拒绝，沿用现有行为。

## Requirements *(mandatory)*

### Functional Requirements

**可见性**

- **FR-001**: 插件 MUST 在启用时挂载本插件配置的全部服务器，与懒加载设置无关。需要授权而尚未授权的服务器保持未连接，授权后挂载。
- **FR-002**: 插件 MUST 为每个会话维护本插件服务器的可见性。会话未显式切换的服务器，懒加载为可见性默认值：懒加载为不可见，非懒加载为可见。
- **FR-003**: 不可见服务器的工具 MUST 不出现在该会话的模型工具集里，也 MUST 不能被该会话调用。
- **FR-004**: 可见服务器的工具 MUST 以宿主原生工具名出现在该会话的工具集里，模型直接调用。
- **FR-005**: 插件 MUST 提供且只提供一个模型工具 `mcp_manage`，参数为 `server` 与 `command`，`command` 取 `active` 或 `inactive`。
- **FR-006**: `mcp_manage` MUST 只改变调用方所在会话的可见性，并在返回值中说明服务器名、新可见性与当前连接状态。
- **FR-007**: `mcp_manage` MUST 拒绝未配置的服务器名与非法 `command`，错误信息列出可用服务器名。
- **FR-008**: 会话的显式可见性选择 MUST 随会话持久保存，会话恢复与压缩后保持不变。
- **FR-009**: 其他插件或设置页挂载的服务器 MUST 不受 `mcp_manage` 控制，也不出现在目录消息里。

**目录与提醒消息**

- **FR-010**: 本插件配置了至少一台服务器时，插件 MUST 保证模型可见的会话上下文中至少有一条反映当前状态的目录消息。
- **FR-011**: 目录消息 MUST 以 system-reminder 形式写入，列出每台服务器的名称、简介与本会话可见性，并说明用 `mcp_manage` 切换可见性、可见服务器的工具以 `mcp__<server>__` 为前缀。
- **FR-012**: 可见性或目录内容变化时，插件 MUST 在该会话下一步写一条更新消息，列出变为可见与变为不可见的服务器，并附完整的当前目录。
- **FR-013**: 状态未变化且目录消息仍在模型可见的上下文里时，插件 MUST 不写新消息。
- **FR-014**: 连接状态变化 MUST 不触发提醒消息。
- **FR-015**: 删除全部服务器后，已收到过目录的会话 MUST 收到一条说明当前没有可用服务器的更新消息。

**服务器简介**

- **FR-016**: 每台服务器定义 MUST 包含非空简介。面板表单 MUST 提供简介字段并校验必填，配置校验 MUST 拒绝缺少简介的定义。

**移除聚合端点**

- **FR-017**: 插件 MUST 移除工具聚合端点、端点令牌、`expose` 配置项与面板端点区块。
- **FR-018**: 插件 MUST 移除 `mcp_call` 与 `mcp_servers` 工具。

**文案与面板**

- **FR-019**: 中文元数据描述 MUST 为「可视化地对MCP进行管理和鉴权；提供MCP懒加载能力」，英文描述 MUST 为对应译文，`package.json` 的 `description` MUST 与英文描述一致。
- **FR-020**: 面板 MUST 只显示一个标题，与插件定位一致，删除重复的品牌字。
- **FR-021**: 面板的连接状态、状态说明、工具数、认证方式选项、停用提示 MUST 经前端字典提供中英文。
- **FR-022**: 面板头部的重新读取按钮 MUST 使用「刷新」语义的独立文案。
- **FR-023**: 前端字典 MUST 删除未使用的键。
- **FR-024**: 英文徽标与开关文案 MUST 使用 sentence case。
- **FR-025**: 其他插件挂载的服务器行 MUST 只显示状态，不显示操作按钮。
- **FR-026**: 面板的懒加载开关 MUST 写回该服务器定义的懒加载设置，作为各会话的默认可见性。

### Key Entities

- **服务器定义**: 本插件配置的一台 MCP 服务器。属性：名称、简介、传输方式与连接参数、认证方式、懒加载。
- **会话可见性**: 一个会话对每台服务器的显式选择 active 或 inactive。未选择时取服务器懒加载的默认值。
- **目录消息**: 写入会话的 system-reminder。记录当时的服务器名称、简介与可见性，作为会话可见性的持久来源。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 模型调用 `mcp_manage` 激活一台已连接服务器后，下一步即可直接调用其工具，无需其他工具中转。
- **SC-002**: 在两个并行会话中，一个会话的可见性切换对另一个会话的工具集影响为零。
- **SC-003**: 任意次数的会话压缩后，模型下一步的上下文 100% 包含一条反映当前状态的目录消息。
- **SC-004**: 每次可见性变化恰好产生一条更新消息；状态不变的步骤产生零条消息。
- **SC-005**: 中英文切换后，插件页与面板中由插件提供的文案 100% 随语言变化。
- **SC-006**: 插件提供的模型工具数量为 1。

## Assumptions

- 后端返回的错误信息与 OAuth 回调结果页保持英文，面板原样显示。
- 面板显示的是服务器的连接状态与默认可见性，不显示某个会话的可见性。
- 升级后已有配置需要为每台服务器补写简介。插件版本为 0.1.x，接受这一不兼容变更。
- 宿主提供按会话限制工具可见性的能力，插件依赖它实现按会话注入。
- `lazy` 的运行时覆盖文件 `state.json` 不再使用，懒加载只由服务器定义决定。
